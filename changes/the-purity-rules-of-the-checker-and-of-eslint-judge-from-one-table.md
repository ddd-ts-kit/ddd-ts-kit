**The three `purity/*` rules of `ddd-ts-kit check` no longer refuse a port method named `fetch`, and see `globalThis.Date.now()`: they judge from the table of their ESLint twins.** `purity/no-system-clock`, `purity/no-ambient-randomness` and `purity/no-environment` had two analyzers with two lists of what is forbidden and two wordings (#883). `ddd-ts-kit check` and `@ddd-ts-kit/eslint-plugin` now read one table per rule (members, calls, constructions, modules, named imports, the names of the global object) with one description and one fix sentence, and a finding says the same thing in both: `process.env is used in the application layer.`

What the checker stops reporting: a method declared under the name of a global (`abstract fetch(id: string): Promise<string>` in a port, `fetch(id) { .. }` in its adapter), and a name the file declares itself, where it is in scope: a parameter (`console: Logger`), a variable, a destructured name, a function, a class.

What it starts reporting, as ESLint did: a global reached through `globalThis`, `window`, `self` or `global` (`globalThis.process.env`, `globalThis.fetch(url)`), `Date()` called as a function, `performance.timeOrigin`, a quoted member (`Date['now']`), an optional one (`process?.env`), `randomBytes`, `randomInt`, `getRandomValues`, `randomUUID` and `webcrypto` imported by name from `node:crypto`, `new (Date)()`, `{ ...process.env }`, and each forbidden key of a destructuring where it is written.

The ESLint plugin stays the authority where the two differ, and its rule pages list where: the checker follows no alias (`const clock = Date`, `import { randomUUID as id }`), and reads as a call a signature that has neither body, return type nor modifier.

To move: run `npx ddd-ts-kit check`. A new finding of a `purity/*` rule names an access to the clock, to randomness or to the environment that ESLint already refused: take it from the `Clock` port, the `IdGenerator` port or a port of the context. The messages of the three rules changed in the checker (`Date.now is used`, where it said `Date.now() is used`): a script that reads them reads the new ones, and a baseline keeps its counts by rule and file.
