**`ddd-ts-kit check` reads what it used to miss: a changed file whose name git quotes.** `check --changed-since <ref>` and `verify-slice --since <ref>` dropped the findings of a file with a non-ASCII character in its name (`café.vo.ts`), because git printed the path quoted: a gate on the changed files passed a file it should have refused. The three commands that ask git what changed (`check --changed-since`, `mutation --changed`, the files of a worker and of a story) now read it through one function, which takes each name as it is on disk and counts a renamed file under both its names. `mutation --changed <ref>` counts from where the branch left `<ref>`, as `check --changed-since` does, so the files the trunk changed meanwhile are no longer listed.

**The checker sees an import whatever stands between its keyword and its specifier.** Four forms let a domain file import infrastructure with `layer/domain-purity` clean: `import(/* a comment */ '...')`, a dynamic import broken over two lines under 20 spaces of indentation, a named list longer than 4000 characters, and a binding named by a string (`import { "a-b" as ab } from '...'`). A statement is now read forward from its `import`, `export` or `require` to its specifier, with no limit of distance. `ddd-ts-kit build`, which rewrites the aliases of the same statements, reads them the same way.

To move: run `ddd-ts-kit check`; an import it did not see is now judged by the layer and context rules.

**A division after `!`, `++`, `--` or `}` no longer hides the rest of its line from the checker.** `return total! / count; const now = Date.now(); const half = count / 2;` was clean for `purity/no-system-clock`: the slash was read as the start of a regular expression, up to the next slash. A slash now divides after a non-null assertion (`total!`, `rows[0]!`, `sum()!`), after a postfix `++` or `--`, and after a closing brace on the same line.

**A suppression names several rules, and one that silences nothing is reported.** A line that broke two rules could not keep a recorded deviation: two `// ddd-ts-kit-disable-next-line` comments one above the other covered the next line only, and `<rule-id>, <rule-id>` was read as one id. A directive now holds a list of ids after commas, and directives one above the other all cover the line of code after the last of them, in `ddd-ts-kit check` and in `@ddd-ts-kit/eslint-plugin` alike. A new rule, `config/unused-suppression` (an error), reports a directive that names an id no rule has, wherever the file is judged, and a directive of a rule that has nothing to report on the line it covers. The second is judged by a run of every rule on every file (`ddd-ts-kit check` without `--rule`; `check-file`, which the guard runs at a file write, never says it), for a rule that is on for the file and that the checker alone holds: for a rule ESLint judges too, the directive is left to stand, since ESLint may find what a reading of the text does not. `config/suppression-needs-reason` is now a rule like the others: a setting of `rules` for some files applies to it.

To move: run `ddd-ts-kit check`. Remove each directive `config/unused-suppression` reports, or correct the id it names; where a directive stood above a comment or a blank line and not above its line of code, move it down.

**`check --clean-only` and `check --baseline` refuse the options they would not honour.** `check --clean-only --changed-since nope src` exited 0: the mode read the directories as they are and ignored the ref, known or not. It is now refused, as is a `--rule` that needs a project (the mode used to run every rule in its place). `--baseline write` and `--baseline prune` refuse `--explain` and `--clean-only` as they refused `--rule`, a path and `--changed-since`.

To move: a script that passes `--changed-since` or a rule outside the `clean/*` ones the mode holds to `check --clean-only`, or `--explain` to `check --baseline`, drops the option.

**`--json` and `--format json` are one thing in `check`, `affected` and `measures`.** Beside another format, `--json` won in `check` and `affected` and lost in `measures`. The three now refuse `--json` with a `--format` other than `json`, and answer a format they do not print with the same sentence and the list of those they do.

To move: a script that passes both `--json` and `--format <other>` keeps the one it reads.
