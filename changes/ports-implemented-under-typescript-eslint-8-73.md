**A freshly installed project lints again: `dddTsKit()` turns off `@typescript-eslint/no-unsafe-class-instance-assignment`, which typescript-eslint 8.73.0 added to its strict preset.** The rule reports a value used where an instance of a class is expected and that the constructor of that class did not build. A port of the kit is an abstract class its adapters implement, and a payload, an answer or a line of a read model is a class built from a literal: every place an adapter is bound to its port or handed to a handler, every fake and every such literal was reported, in a project `init` had just written and installed from 2026-11-16, the day 8.73.0 was published. The rule has no option, so it is off as a whole: a plain object passed where `instanceof` or the metadata of a decorator is expected is no longer reported by it. The preset names the rule only where the installed typescript-eslint holds it, so a project on an earlier 8.x keeps working, and `standardRules.kitConventions` carries the same line for a configuration composed by hand.

To move: update `@ddd-ts-kit/eslint-plugin` with the kit; nothing to write. A project that cannot update yet and whose `npm install` took typescript-eslint 8.73 adds `'@typescript-eslint/no-unsafe-class-instance-assignment': 'off'` to the rules of its `eslint.config.js` until it does.
