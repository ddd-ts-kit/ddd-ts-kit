**`cached` keeps the entries of each port of each context apart, and counts a cache that fails.** The key of an entry was the class name, the method and the key of the call: two adapters of one class name in two contexts, or two instances of one class bound under two ports, read each other's entries. The key now holds the context and the port the instance is bound to (its class name when it has no port), then the method and the key of the call. An object that has neither a port nor a class name, an object literal for one, is refused when it is wrapped, with an `AspectNotAllowedError` that names the method: pass `{ token }` or `{ className }` as the second argument of the aspect. A read or a write the cache fails is still a miss, and is now counted as `cache_errors_total`, labelled `operation`, `context`, `class` and `method`, on the new `metrics` option or on the metrics of the aspect runtime (#903).

To move: nothing for an instance wrapped without context and without port, whose key does not change. The entries of an instance bound through `aspects(...)` of the composition root are read under their new key: the old ones expire with their `ttlMs`.
