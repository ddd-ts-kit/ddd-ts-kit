**The test DSL of `@ddd-ts-kit/testing` reads a refusal, a waiting scenario and a builder as the test wrote them.** Six defects, and four alignments in the same files (#879).

- `pending(...)` holds a scenario that waits with `until` or `settled`: both now fail with an `AssertionError`, where their plain `Error` made `pending` call the scenario broken.
- `expectRefusal` awaits a promise, the one an action returns or one given in its place (`await expectRefusal(bus.execute(command), code)`), and reads what it answers as it reads a synchronous answer. An asynchronous action that answered a refusing `Result` read as "nothing was refused", and a promise given directly was taken for the error, its rejection left unhandled.
- After `thenError`, `thenNoEvent`, `thenEvents` and `thenEventNames` read the events the action recorded before it threw, as `thenState` already read the aggregate: `.thenError('ORDER_ALREADY_PAID').thenNoEvent()` asserts a refusal that recorded nothing.
- A builder copies its plain data (object literals and lists) at each build, in the defaults and in what `with` was given: a nested object of the defaults was shared by every build, so changing a built value changed the next one. An instance of a class is handed as it is.
- `given(aggregate)` refuses a second `when` with a `TypeError`: it ran on the aggregate the first one had changed, where `given(builder)` and `scenario(() => aggregate)` start each `when` from a fresh one.
- A `Builder` subclass declares no `#private` field: a step copies the builder without running its constructor, so such a field is absent from the copy. The rule is now stated on the class and in the README; a field declared `private` or `readonly` follows the copy.
- An event or command matcher by properties is a subset inside a list too, read position by position (`{ lines: [{ sku: 'pen' }] }` matches a line that carries more), and names at least one property: `{}` is refused.
- `expectProblem` shows what was expected, what was received and the body of the answer when it fails.
- `givenProcess(...)` fails as a scenario does: a sentence, then the commands or timeouts expected and decided, and where they differ, positions from 1 (`command 1.invoiceId: expected 'invoice-2', decided 'invoice-1'`).

To move: a spec that compares by identity (`toBe`) a plain object it gave to a builder compares it by value (`toEqual`); a spec that runs two `when` on one `given(aggregate)` gives the builder, or `scenario(() => aggregate)`; an event or command matcher `{}` becomes the name or the class; a spec that asserts the text of a failure of `givenProcess`, or of `expectProblem`, reads the new one.
