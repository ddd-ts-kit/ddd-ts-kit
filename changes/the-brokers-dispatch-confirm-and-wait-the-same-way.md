**Redis Streams hands each handler the events of its type on a stream several types share.** With a `streamOf` that maps several event types to one stream, `RedisStreamsEventBus` gave every handler of the stream every entry, whatever its type, and `describeTopology()` kept the first type only. A handler now receives the events of the type it subscribed to, as on Kafka with `topicOf`; an entry of a type the consumer never subscribed to is acknowledged unhandled, and `describeTopology()` lists every type (#901).

**RabbitMQ bounds every confirmation it waits for with `publishTimeoutMs`.** Only a publication was bounded: the copy of a failed message to its retry or dead queue, and each copy of `replayDead`, waited for ever on a broker that stopped confirming (a disk alarm), so the delivery held its prefetch slot and `close()` never returned. The three paths now share one bounded confirmation: a copy that is not confirmed in time hands the message back to its work queue, `replayDead` rejects with `PUBLISH_NOT_CONFIRMED` and leaves the message dead, and `close()` returns (#901).
