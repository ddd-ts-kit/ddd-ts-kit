**Redis Streams hands each handler the events of its type on a stream several types share.** With a `streamOf` that maps several event types to one stream, `RedisStreamsEventBus` gave every handler of the stream every entry, whatever its type, and `describeTopology()` kept the first type only. A handler now receives the events of the type it subscribed to, as on Kafka with `topicOf`; an entry of a type the consumer never subscribed to is acknowledged unhandled, and `describeTopology()` lists every type (#901).

**RabbitMQ bounds every confirmation it waits for with `publishTimeoutMs`.** Only a publication was bounded: the copy of a failed message to its retry or dead queue, and each copy of `replayDead`, waited for ever on a broker that stopped confirming (a disk alarm), so the delivery held its prefetch slot and `close()` never returned. The three paths now share one bounded confirmation: a copy that is not confirmed in time hands the message back to its work queue, `replayDead` rejects with `PUBLISH_NOT_CONFIRMED` and leaves the message dead, and `close()` returns (#901).

**Kafka's `assertTopology()` resolves for every caller when a subscription is added while the group joins.** A subscription made before the coordinator answered the previous join replaced the promise the earlier callers were waiting on, so their `assertTopology()` never resolved and a composition root that awaited it before listening never started. A member now holds one wait at a time, shared by whoever asked during the join (#901).

**A message whose handlers all unsubscribed is kept for the next handler the same way on the four brokers.** It is never acknowledged, never sent to the dead destination, reported as no failure and never delivered again on the spot. RabbitMQ requeued it at once and NATS refused it without a delay, both in a hot loop until the consumer was gone; Redis Streams counted each redelivery and buried it as `ATTEMPTS_EXHAUSTED` without a handler having seen it. RabbitMQ now sends it to the retry queue with its `x-attempt` unchanged, NATS refuses it with `retry.delayMs`, Redis Streams leaves it pending with that delivery taken off its counter, and Kafka goes on holding its partition until a handler subscribes. It counts as no attempt, except on NATS, where the server counts each delivery (#901).
