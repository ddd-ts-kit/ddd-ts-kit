**The generators edit a source file where they read its code, or refuse.** A generator that adds to a file a team has edited now finds the place in the code of the file, never in a comment or a string that looks like it, and stops with what to write by hand when it cannot tell the place.

- `generate ... --grant <role>`: the grant is written in the list of the role named, or refused when that list cannot be read. A role whose grants are a named constant (`[Role.Admin]: EVERYTHING`) is refused with the grant to write by hand; a role keyed by its value (`admin: [...]`) is found; an object of roles written on one line is refused.
- An import a generator adds follows the last import of the file whatever its style: without semicolons, with double quotes, on several lines, with a comment after it. It was written inside the first function of a file formatted without semicolons. A file that already binds the name, however its statement is written, is left as it is.
- `generate error` adds a factory in the body of the error class, after its type parameters and what it extends: a class written `extends Refusal<{ invoiceId: string }>` had the factory written inside that type. A factory that returns an object type is followed after its block.
- The `imports` region of a wiring file is merged statement by statement. An import written on several lines with a comment after a name is kept as it is written, and a new name of its module is imported beside it: the statement was folded into one line whose comment swallowed the names after it. An import written with double quotes or without a semicolon takes the new name in its own style, where the name was imported a second time.
- The Prisma main schema is edited inside its `datasource` and its `generator client` blocks: a comment that shows a list is left alone, `schemas = []` becomes `schemas = ["billing"]`, a list on several lines keeps its commas, and the preview features go to the generator of the client when another generator has the same body. A datasource that lists no `schemas` is refused with the line to write, where the schema of the context was silently left out.
- A concept named after a reserved word of the language (`Return`, `Case`, `Default`, `Package`, `Class`, `Import`...) or after a global the generated code uses (`Date`, `Error`, `Record`, `Map`, `Set`, `Promise`...) is refused at once, with the reason, whatever the flags: `generate command --aggregate Return --creates` wrote `const return = Return.create(...)`, and an aggregate `Date` a class that hid the `Date` of its own factory.
- A name is read the same whatever the separators it was typed with: `"credit 2 note"`, `credit-2-note` and `Credit2Note` all write `credit2-note.aggregate.ts`, the file every later command looks for. `generate aggregate billing "credit 2 note"` wrote `credit-2-note.aggregate.ts`, which `generate repository billing Credit2Note` did not find.
