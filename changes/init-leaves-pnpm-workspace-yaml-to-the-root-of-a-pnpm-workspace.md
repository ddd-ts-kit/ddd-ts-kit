**`init` writes no `pnpm-workspace.yaml` in a package of a pnpm workspace.** pnpm takes the nearest `pnpm-workspace.yaml` as the root of a workspace, so the file `init` wrote in `packages/api` cut the project out of the workspace that lists it: an install from the package wrote a second lockfile and applied overrides the install from the root never read. When the nearest `pnpm-workspace.yaml` above lists the project in its `packages`, `init` now writes none, and a note says what the root file lacks of what the stack needs (`strictDepBuilds: false`, the `overrides`, the `allowBuilds` entries). `ddd-ts-kit sdk` asks the root file to list the clients, and `doctor` reads the overrides and the allowed build scripts there. A project under a workspace that does not list it keeps a file of its own.

To move: in a project that is a package of a pnpm workspace, copy `strictDepBuilds`, `overrides` and `allowBuilds` from its `pnpm-workspace.yaml` to the one of the workspace root, delete the file and the `pnpm-lock.yaml` beside it, then run `pnpm install` from the root.
