**`ddd-ts-kit merge-trunk` keeps each table whole when both sides added one to the same context.** Two branches that each stored an aggregate in one context each add a table to its tables file, at the same place. git sets the two side by side and keeps the lines they share once, their last ones, and the merge then kept "the lines of both sides" of the conflict: the tables file it committed, exit 0, held two tables with the closing lines of one (`TS1005 '}' expected`), on the four ORM: the tables file of the context on Drizzle and on TypeORM, `create-<context>-tables.schema.ts` on Knex, `prisma/schema/<context>.prisma` on Prisma, the context flat or laid out in modules. The schema index was right, and still is.

The lines of both sides are still what a conflict inside a generated region keeps: the report says `generated registry: the lines of both sides kept` and the region is written as it was before this change, in every case but two. The first: the region those lines give does not pair its brackets, the case above. The second: in one conflict, two different statements that each hold a bracket open across several lines open on the same line or close on the same line (two `platform.commands.register(` written on several lines), a line the union keeps once; a chain written on several lines with no bracket across them is not seen; a statement both sides added alike does not count, it is kept once as before. In these two cases the region of a TypeScript, JavaScript or Prisma file is merged declaration by declaration instead, from the three sides of the file. The declaration each side added is kept whole; one both added alike is kept once; one a side changed or removed while the other left it as the base holds it follows that side; one both changed takes the merge of its lines, as git merges a file, when they merge without a conflict: a line one side removed stays removed. The declarations both sides hold stand in the order of the side that changed their order, ours when neither did, and what a side alone adds stands after the declaration it follows on that side, or first when it opened the region there. The report then says `generated registry: the declarations of both sides kept, each one whole`, in a dry run too, and `generated registry: the declarations of both sides kept, each one whole, and the lines of both sides kept` when another region of the file kept the lines of both sides.

What the kit does not merge this way is left to you. A declaration both sides wrote differently (two tables of one name with different columns, one of them with one more column included, a table both changed whose lines do not merge, a table one side changed and the other removed) is one hunk that holds each version whole, the rest of the region being merged, and the report names it when both sides hold it: ``the two sides do not agree on `invoices` in the region `tables`: for each, write the one declaration that keeps the intent of both, whole, or remove it.`` In the cases that follow nothing is written in the region, the hunks git wrote stay, those of a region written inside it too, and the report says why and what to write, each declaration of both sides whole, once, in most cases, where it said `both sides only add lines: keep both`: a bracket that does not pair, a regular expression, a region written inside it, two declarations of one name on one side, a side that does not hold the region once; a statement that declares no name (a call written on several lines) which a side changed or removed; lines that end no statement (entries of a list, or statements written without `;`) on which the two sides differ; two statements with no declared name that open alike, one holding every line of the other, which nothing tells from one statement written twice; declarations both sides set in two different orders; a default export on each side, written `export default` or `export { name as default }` on one line, a file having one (another spelling, `export { default } from`, a list on several lines, is not seen, and a line of that shape in a comment or a template literal counts); merged lines that would not read back as the declarations merged.
