**A command of `ddd-ts-kit` declares itself once, and `check` reads the options of one of its modes at a time.** What was said of a command (its name, its options, its usage, the lock it takes) lived in several places joined by its name; it is one declaration in the file of the command, which the entry, `--help`, the usage a refused argument is answered with and `docs/guides/commands.md` read. `--help` and `--help --json` print what they printed, but for the lines of `check`. What changes for who runs the CLI:

- `ddd-ts-kit check` is five commands under one name, each with its own options and its own usage line: the check of a project, `--baseline write|prune`, `--clean-only <dir>...`, `--commit-size` and `--self`. The mode whose option comes first on the command line runs. An option another mode declares is refused with the reason of the mode asked, and the usage line of that mode as the fix. The refusals that change:
  - `check --baseline write|prune` beside `--rule`, `--changed-since`, `--explain` or `--clean-only` said `--baseline write judges every rule on every file.` with `Run it without --rule, a path, --changed-since, --clean-only or --explain.`; it says `check --baseline does not take --rule: it judges every rule on every file.` with `ddd-ts-kit check --baseline write|prune`. The same answers `--format`, which was read and ignored, `--self`, which ran instead, and `--commit-size`, `--staged` and `--strict`, which the parser refused (`Unknown option '--staged'.`).
  - `check --baseline write src` said `--baseline write judges every rule on every file.` with the same fix; it says `check --baseline does not take a path: it judges every rule on every file.` with `ddd-ts-kit check --baseline write|prune`.
  - `check --clean-only --changed-since <ref>` said `--clean-only compares with no ref.` with `Run it without --changed-since: it judges the directories given as they are, outside a project and its history.`; it says `check --clean-only does not take --changed-since: it judges the directories given as they are, outside a project, its history and its baseline.` with `ddd-ts-kit check --clean-only <dir>... [--rule <id>]... [--format text|json|github|gitlab] [--explain]`. The same answers `--baseline`, `--commit-size`, `--staged`, `--strict` and `--self`.
  - `check --commit-size --rule <id>` (and `--format`, `--changed-since`, `--explain`, `--baseline`, `--clean-only`, `--self`) said `Unknown option '--rule'.` with the four lines of `check`; it says `check --commit-size does not take --rule: it measures what is about to be committed and runs no rule.` with `ddd-ts-kit check --commit-size [--staged] [--strict]`.
  - `check --self --rule <id>` (and `--format`, `--changed-since`, `--explain`, `--baseline`, `--clean-only`, `--commit-size`, `--staged`, `--strict`) replayed the fixtures and ignored the option; it says `check --self does not take --rule: it replays the fixtures shipped with the CLI, whatever the project.` with `ddd-ts-kit check --self`.
  - `check --staged` or `check --strict` without `--commit-size` said `Unknown option '--staged'.` with the four lines of `check`; it says `--staged is an option of check --commit-size.` with `ddd-ts-kit check --commit-size [--staged] [--strict]`.

  An option no mode knows is still answered by the parser (`Unknown option '--nope'.`), with the usage line of the mode asked, or the five lines of `check` when none is. The usage of `check` follows: `--self` has its line and leaves the first one, and the line of `--clean-only` shows what it has always accepted, `--format text|json|github|gitlab` and `--explain`.
- An option that takes one of a few values is held to them by the parser, in one sentence: `Unknown value "<value>" for --<option>.` with `Use one of: <values>.`. It replaces `Unknown gate "<value>".` (`acceptance --gate`, `story --gate`), `Unknown kind "<value>".` (`story-scope --kind`), `"<value>" is not a form error-factories moves a project to.` (`error-factories --to`) and `Unknown --baseline "<value>".` (`check --baseline`). Such a value is refused before the command reads the project.
- An unknown command is answered with the commands in the order of `--help`.
- A refusal read as JSON, and the package manager its fix is written for, follow `--json` and `--cwd` as the commands read them: `--cwd=<dir>` counts, a `--json` after `--` does not.

To move: a script that matched one of the sentences above matches the new one; the exit code, 2, is the same. A script that ran `check --self` or `check --baseline` with an option they ignored drops the option: the command line exits 2.

For who writes a command of the kit: `CONTRIBUTING.md` says what a command file holds (#918).
