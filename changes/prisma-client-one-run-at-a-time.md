**On Prisma, two test runs started together in one project no longer break each other's client (`ddd-ts-kit prisma-client`).** `npm run db:client`, which `pretest`, `pretest:e2e`, `pretypecheck` and `prebuild` run, was `prisma generate && prisma migrate diff ... -o generated/schema.sql`: two runs at once (two `npm run test:e2e`, a type check beside the tests) both removed and wrote `generated/prisma`, and one failed on `EEXIST` or `ENOENT`, or read a client the other was rewriting. `init` now writes `"db:client": "ddd-ts-kit prisma-client --schema prisma/schema"`. The command runs the same two steps, one run of the project at a time (the lock `.ddd-ts-kit/prisma-client`, waited for up to ten minutes, taken over once the run that holds it has ended), and writes nothing when the client and `generated/schema.sql` are current: generated from the same files of the schema, the same `prisma.config.ts` and the same `prisma` and `@prisma/client`, and still there. What they were generated from is kept in `generated/prisma-client.sha256`; removing `generated/` generates them again.

To move: in `package.json`, set the `db:client` script to `ddd-ts-kit prisma-client --schema prisma/schema` (`--schema prisma/schema.prisma` for a project that still keeps its schema in one file).
