**A domain event has a rank in its aggregate and an identity that follows from it, and a read model applies every event one command records.** A `DomainEvent` said its name, its instant and its aggregate, and nothing told two events of one aggregate apart: `stampOf` invented `<name>:<aggregateId>`, so of two events recorded at the same instant a read model kept the first and answered `stale` to the second, whichever the alphabet put last, and always under a fixed clock. The aggregate now gives each event it records its rank in its history, from 1 (`rankOf(event)`), and the identity of the event is `eventIdOf(event)`, `<name>:<aggregateId>:<rank>`: nothing is drawn, so the event a save dispatches and the same event read back from its stream are one. `stampOf(event)` of a domain event carries that identity and, as `version`, the rank: the rows of one aggregate follow its history, not the clocks, and the read model contract of `@ddd-ts-kit/testing` proves it on every store. What invented an identity reads it: `EventSerializer` stores an event under `eventIdOf(event)` and gives the event it reads back the rank of its stream, the side table behind `storedStampOf` is gone, and a projection fed by the event store and by the saves stamps both with `stampOf(event)`.

A save moves the version of an aggregate to the rank of the last event it recorded, and by one when it recorded none, where it moved by one whatever was recorded: the next event of the aggregate ranks after every one before it, across saves and loads. `optimisticUpdate` computes it, so every repository adapter follows without a change, and the `version` column of a table keeps its rows: a version only has to grow. The version of an event-sourced aggregate was already the rank of its last event.

To move: `storedStampOf(event) ?? stampOf(event)` no longer compiles (`TS2724`): write `stampOf(event)`, and `rankOf(event)` where the code read `stamp.version` of a domain event.
To move: `stampOf(domainEvent, version)` no longer compiles (`TS2554`): a domain event brings its own version. A key that the domain events of several aggregates write has no single history: stamp it `{ eventId: eventIdOf(event), occurredAt: event.occurredAt }`, and the instants decide as they did.
To move: a spec that builds a domain event by hand and hands it to a projection or to `EventSerializer.serialize` is refused with `has no rank: no aggregate recorded it`: say where the fact stands, `ranked(new InvoiceIssued('inv-1', now), 1)`, or let the aggregate record it and read `recordedBy(aggregate)`.
To move: one event object recorded by two aggregates, or twice, is refused (`already stands at rank`): build an event per fact.
To move: `new EventSerializer(types, { ids })` no longer compiles (`TS2353`): drop `ids`. An event store already holding events needs no migration: its rows keep the id they were stored under, the new ones are stored under `<name>:<aggregateId>:<rank>`, and both are read back with the same stamp, the rank of the stream. An `EventStore` adapter of your own that keeps the id in a `uuid` column changes it to text before the first append of this version.
To move: a read model fed by the domain events of state-stored aggregates holds rows stamped without a version. They need no migration: against such a row the instants decide, as before, until an event of this version writes it. Rebuild the read model if two events of one instant may still meet an old row. A read model fed by the event store keeps its rows as they are: the version of a row was already the rank of its event.
To move: code that counted the saves of an aggregate by its `version` (a spec expecting `2` after two saves) reads the rank of its last event instead: a save that records three events moves the version by three.
