**Each refusal and each question of the guard of the plugin opens with the id of the rule that took it.** The message reads `ddd-ts-kit [worker-scope]: You build the context "ordering": ...`, `ddd-ts-kit [held-changes]: Your commands, or another session, changed files outside your scope: ...` or `ddd-ts-kit [governed-file]: biome.json holds the rules or the pipeline ...`, on Claude Code, Codex and Copilot alike, where it used to open with `ddd-ts-kit: `; the sentence after the id is unchanged. A report to the conductor, an issue or a deviation can cite the rule by its id. Inside the guard, each chain of rules is now a table of rows `{ id, applies?, reason }` asked in its order, with no other change of answer. A project has nothing to do; a script that read the message by its `ddd-ts-kit: ` prefix reads `ddd-ts-kit [<id>]: ` now.
