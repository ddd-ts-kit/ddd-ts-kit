**`init` says how a package of a workspace builds its image.** The `Dockerfile` that `init` writes copies the manifest and the lockfile of its folder, and a package of an npm or pnpm workspace has no lockfile: the root of the workspace holds it. `init` still writes the same file, and a note now says that the image builds from the root (`docker build -f packages/api/Dockerfile .`) and what to change in the file: the manifest and the lockfile of the root copied with the `package.json` of the package, the install and the build filtered on the package (`npm ci --workspace packages/api`, or `pnpm install --frozen-lockfile --filter ./packages/api...`), and the same folders kept in the last stage. A project under a workspace that does not list it installs alone and gets no note.
