**A rule of `ddd-ts-kit check` says everything about itself in its own file.** Its default severity, the explanation `ddd-ts-kit explain` shows and whether `check --clean-only` runs it were three tables keyed by the rule id, beside the rule; they are fields of the rule, required by the compiler, and the tables are gone. A rule that reads one source at a time now receives that source and answers what it finds, and the checker walks the sources: such a rule can ask for the config, the place of a file and a source it imports, never for the other sources, so `ddd-ts-kit check-file` and `ddd-ts-kit check` cannot disagree on it unseen. No rule id, message, severity or output changes, with one exception: when a file of a published language declares the same version of an integration event twice and another file declared it first, `events/defined-in-published-language` reports the second declaration against its own file, where it named the other one.

For who writes a rule of the kit: `CONTRIBUTING.md` says what a rule file holds (#905).
