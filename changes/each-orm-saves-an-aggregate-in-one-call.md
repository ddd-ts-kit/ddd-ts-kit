**Each ORM package saves an aggregate in one call: `saveAggregate`, and `saveTenantAggregate` for a table every tenant shares.** A repository adapter used to carry the optimistic-concurrency plumbing itself: `optimisticUpdate`, an insert that ignores a taken key, an update guarded by the version, the audit stamps, the tenant on the inserted row and in the condition of the update. `@ddd-ts-kit/knex`, `@ddd-ts-kit/drizzle`, `@ddd-ts-kit/prisma` and `@ddd-ts-kit/typeorm` now each export the two functions, which take where the row lives (a table, a model, an entity) and one save: `{ aggregate, row: Mapper.toRow(aggregate), scope, clock }`. The row is inserted at version 1 with its creation stamp the first time, then updated while it still holds the version the aggregate was loaded at; a taken key or a row that moved is a `ConcurrencyError`, a value another row holds a `UniqueViolationError`, as before. `saveTenantAggregate` writes the row in the tenant of the work in progress and confines its update to that tenant. Both are made of `saveAggregateRow` of `@ddd-ts-kit/kernel`, which an adapter over another store can call with its own two statements.

A generated repository, those of the identity preset included, now declares its table, its mapper and its lookups, and saves in that one call: no `insert`, no `update`, no `Versioned<Aggregate>` type, no stamp. On Knex it names its table once (`const TABLE = { schema, table }`) and reads it through `tableIn(database, TABLE)`, which `@ddd-ts-kit/knex` now exports, or `tenantTable` on tenant data. In a multi-tenant project, `tenancy/scoped-statement` reports an aggregate saved with `saveAggregate`, which names no tenant, and reads a Prisma model handed to `saveTenantAggregate` as confined.

To move: nothing has to: a repository written on `optimisticUpdate` works as before. To shrink one, replace its `save`, `insert` and `update` by `await saveAggregate(<database>, <table>, { aggregate: saved, row: Mapper.toRow(saved), scope: this.scope, clock: this.clock })` (`saveTenantAggregate` where it spread `tenantScopeOf` and an own-tenant condition; on Prisma the first argument is the model alone, `this.database.client().<model>`), then drop the `Versioned<Aggregate>` type and the imports left unused. Keep a `try` around the call where the save translated an error of the database. A repository with no lookup of its own can be generated again: `ddd-ts-kit generate repository <context> <Aggregate> --force`.
